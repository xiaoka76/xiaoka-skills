
## 四、分辨率

**图片生成场景**（draw/edit/cutout）：档位 `1K` / `1.5K` / `2K`（推荐），或自定义 `宽x高`，**不可混用**。

**图层拆分场景**（split）：**仅档位** `1K`/`1.5K`/`2K`/`auto`，不支持自定义宽x高。

档位在不同宽高比下的实际像素值：

| 分辨率 | 1:1 | 4:3 | 3:4 | 16:9 | 9:16 | 3:2 | 2:3 | 21:9 |
|--------|-----|-----|-----|------|------|-----|-----|------|
| 1K | 1024x1024 | 1152x864 | 864x1152 | 1424x800 | 800x1424 | 1248x832 | 832x1248 | 1568x672 |
| 1.5K | 1536x1536 | 1792x1344 | 1344x1792 | 2048x1152 | 1152x2048 | 1872x1248 | 1248x1872 | 2352x1008 |
| 2K | 2048x2048 | 2368x1776 | 1776x2368 | 2816x1584 | 1584x2816 | 2496x1664 | 1664x2496 | 3136x1344 |

- 档位模式下，宽高比用自然语言写进 prompt（如 `--size 2K` 配合 prompt 写"宽高比 16:9"）。
- `1.5K` 与 `1K` 价格相同、画质更优，性价比档位优先选 `1.5K`。
- 自定义像素：总像素 `[921600, 4624220]`（`1280x720` ~ `2048x2048x1.1025`），宽高比 `[1/16, 16]`，两条件需同时满足。

**图层拆分输出**：底图分辨率与 `size` 档位一致、宽高比与原待拆分图一致；各图层分辨率与 `size` 接近、宽高比与原图中该图层一致。

**图层拆分 `auto` 适配规则**（按输入图中底图与每个图层的原始尺寸决定）：

- 原始尺寸落在 `[921600, 4624220]` 总像素区间内 → 按**原尺寸**输出，各自保持原宽高比
- 原始尺寸**小于 1K** → 按 **1K** 输出
- 原始尺寸**大于 2K** → 按 **2K** 输出

## 五、参考图约束

单张参考图必须同时满足：

| 约束项 | 要求 |
|--------|------|
| 格式 | `jpeg`、`png`、`webp`、`bmp`、`tiff`、`gif`、`heic`、`heif` |
| 宽高比（宽/高） | `[1/16, 16]` |
| 宽高长度 | 均 **> 14 px** |
| 大小 | ≤ 30 MB |
| 总像素（宽×高） | `[196, 6000×6000]`（196 ~ 3600 万） |

- 张数：图片生成场景最多 **10 张**；图层拆分场景**仅 1 张**，且格式仅 `png`/`jpeg`、总像素 `[512×512, 6000×6000]`。
- 以上约束**都会在本地先校验**（读图片尺寸/大小）。超限时直接给出可执行的缩放建议、**不自动改图**：

```
错误: 参考图总像素超限: big.png（8000x6000 = 4800 万像素，上限 3600 万像素）。
      建议先等比缩放到 6928x5196 再传入——这一步交给你决定，不会自动改图
```

`split` 还有一套更严的专属预检（格式仅 png/jpeg、总像素 `[512×512, 6000×6000]`），小图会给**放大**建议。

### 与「LLM 读图」的限制对照（官方文档实测）

| 项 | 火山方舟**视觉理解**（LLM 读图） | Seedream 5.0 **图生图** |
|----|--------------------------------|------------------------|
| 硬性像素范围 | 宽×高 `[196, 36,000,000]` | 总像素 `[196, 36,000,000]` |
| 宽高长度 | > 14 px | > 14 px |
| 宽高比 | `[1/150, 150]`（更宽松） | `[1/16, 16]` |
| 单张文件大小 | Base64 / URL 方式 **< 10 MB**（Files API ≤ 512 MB） | ≤ 30 MB |

像素范围完全一致，差别只在宽高比与文件大小。

> 补充事实：LLM 读图会按 `detail` 档位把图等比缩放进对应像素区间，`doubao-seed-2.0` 及以后默认
> `detail=high`（单图固定 1280 token，像素区间上限约 226 万）；token 按 `min(宽×高 ÷ 1764, 单图上限)`
> 估算，**超出部分会被压缩、细节丢失**。所以预览图不是越大越清晰——超出区间会被模型侧再压回去。

## 六、图层拆分的产出与还原

命令行会打印底图、图层数量、每个图层的 `z_index` / 名称 / **像素 bbox** / **可直接写进 prompt 的
`<bbox>` 标签**；完整信息落在该次任务的 `run.json`。还原或重组图层时：

1. 把 `z_index = 0` 的对象（底图）作为画布背景
2. 其余图层按 `z_index` 从小到大排序后依次叠放
3. 按像素 bbox 把图层放到目标画布：

```
x = left, y = top, w = right - left, h = bottom - top
将图层缩放到 w×h，放到底图的 (x, y)
```

> 想改到别的画布尺寸：把上面四个值按目标画布与原图的比例（W/原宽、H/原高）等比缩放即可。
>
> `run.json` 里每个图层给两套坐标，**用途不同**：`bbox_base` + `bbox_base_size` 为**底图坐标系**（图层分辨率与底图一致），**还原/重组用这个**；`bbox_pixel` / `prompt_fragment` 为**原输入图坐标系**（像素），**写进 prompt 继续编辑用这个**。字段全表见 `run-format.md`。

## 七、标记预览 `mark`

```bash
seedream mark <图> [--point x,y[:标签]] [--box x1,y1,x2,y2[:标签]] [--grid/--no-grid] [--plain] [-o 路径] [--max-edge N] [--json]
```

| 参数 | 说明 | 默认 |
|------|------|------|
| `<图片>`（位置参数） | 原图路径（**不支持 URL**，先下载到本地） | 必填 |
| `--point x,y[:标签]` | 点选坐标（像素，可多次指定） | — |
| `--box x1,y1,x2,y2[:标签]` | 框选坐标（像素，可多次指定） | — |
| `--grid` / `--no-grid` | 预览图是否叠加坐标网格 | 开启 |
| `--plain` | **提交模式**：输出纯标记图（无网格/无文字），**默认严格原图尺寸**，可直接作参考图传给模型；要控体积再显式加 `--max-edge` | 关闭 |
| `--out` / `-o` | 输出路径（后缀决定格式：`.jpg` 默认，`.png` 无损） | `<数据根>/mark/<id>.jpg` |
| `--max-edge` | 输出最长边上限；`0` = 强制原始尺寸且不降档 | 预览模式自动，提交模式 `0` |
| `--json` | 以 JSON 输出结果 | 关闭 |

- **两种模式**：预览模式（默认，原图 + 留白网格 + 彩色标记 + 标签，用于核对坐标）；提交模式（`--plain`，纯标记图，用于当输入）。
- 标记编号顺序：**点选在前、框选在后**。`--json` 每项给 `pixel`（原图像素）与 `fragments`（成品标签，也是像素）。
- 标签用冒号内联：`--box 100,80,420,320:手部`（不传标签也能用）。

**网格**（默认开启）：

- 刻度数字一律画在**图片外的留白区**：上方（横坐标）右对齐于所在竖线、贴留白底部；左侧（纵坐标）右对齐于图片左边界、位于所在横线上方。
- 留白宽度按**最宽的刻度数字**自动撑开，保证数字不压进画面也不被裁掉；**留白只留在上方与左侧**（画布更小、视觉模型 token 更少、同预算下图片显示更大），图片边框也只画上、左两条。
- **刻度包含边界值**：右上角 `x = 图片宽度`、左下角 `y = 图片高度`，纵轴还标出 `y = 0`（`x = 0` 与左上角纵轴标签重叠，不单独标）。
- 刻度值**始终是原图像素**，即使预览图被缩放，读到的数字也可直接传给 `--box`。
- `--no-grid` 关闭网格（只想要干净原图时用）。

**输出格式与分辨率**：默认输出 `.jpg`（体积小、各视觉模型都能读），需要无损用 `--out x.png`。分辨率默认**自动**——先按原图尺寸渲染，产物达 **2MB**（平台内联预览上限）时自动逐档降分辨率重渲染，直到压进限制；要强制原始尺寸加 `--max-edge 0`，要自定上限加 `--max-edge 2048`。

**标记自动避让**：标签块按优先级择优（上方 → 下方 → 标记内部 → 右侧 → 堆叠），主动避开已放置的标签，最后统一夹回画布内——不会被其他标记的填充/描边盖住，不会超出边界被裁掉，多个标记挤在一起时自动错行堆叠。

**依赖**：绘制时标签含中文会自动切换中日韩字体；系统若无中日韩字体，会移除标签中的非 ASCII 字符并提示（**不影响坐标正确性**）。

## 八、提示词优化模式（`--optimize`）

| 模式 | 说明 |
|------|------|
| `standard` | 标准模式（默认），质量更高、耗时较长 |
| `fast` | 快速模式，耗时更短、效果略低 |

- **`fast` 仅 5.0 pro 支持**：官方明确 5.0 flash / 5.0 lite / 4.5 当前不支持 `fast`（本技能固定 5.0 pro，两种模式都可用）。
- 官方建议：对生成时延敏感时，用 5.0 pro 的 `fast`，或改用更快的 5.0 flash 模型。

## 十、文生图 prompt 自查（反例）

文生图 prompt 必须覆盖 6 维度（主体 / 场景 / 风格 / 光影 / 构图 / 质量）。以下是**简短 prompt 的典型错误**，不得生成此类 prompt：

| 错误示例 | 问题 |
|----------|------|
| `"一只猫"` | 只有主体，无场景、风格、光影、构图、质量词 |
| `"美丽的风景"` | 过于笼统，无任何具体细节 |
| `"科技风海报"` | 只有风格意向，无主体、场景、构图 |
| `"一个穿西装的商务人士"` | 缺少场景、光影、风格、构图描述 |

合格示例（覆盖所有维度，约 80 字）：

```
"黄昏时分的赛博朋克茶馆，雨水顺着发光的霓虹窗户流下。屋内，一位银发少女坐在窗边，捧着一杯热茶。
窗外，全息龙形灯笼在雨街上漂浮。细节丰富，电影级光影，超精细8K。"
```
